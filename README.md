# مطابع روعة التصاميم .. طباعة شاملة (RD Amazing)

موقع مطبعة **مطابع روعة التصاميم** في الدمام، المملكة العربية السعودية.
المرحلة الحالية: موقع ثابت (HTML/CSS/JS)، وبعدها يتحوّل إلى PHP + MySQL مع لوحة تحكم بنفس التصميم حرفياً.

**الموقع مباشر:** https://engmohammad-hash.github.io/rd-amazing-nidal/

## الصفحات

| الصفحة | المسار | المحتوى |
|---|---|---|
| الرئيسية | `/` | فيلم سكرول (صمّم ← اطبع ← فخامة ← استلم)، المنتجات، لماذا نحن، خطوات العمل، رؤية ٢٠٣٠، آراء |
| منتجاتنا | `/products/` | كل المنتجات |
| صفحة كل منتج | `/products/<slug>/` | فيلم سكرول خاص بالمنتج، المواصفات، أزرار الطلب، معرض ٦ صور، منتجات أخرى |
| أعمالنا | `/works/` | معرض كل الصور مع تصفية حسب المنتج وعرض مكبّر |
| من نحن | `/about/` | القصة، ما يميّزنا، رؤية ٢٠٣٠، خطوات العمل |
| آراء العملاء | `/reviews/` | آراء (تجريبية حالياً) |
| تواصل معنا | `/contact/` | واتساب، اتصال، بريد، إنستغرام، الموقع، ساعات العمل (مفتوح/مغلق الآن بتوقيت السعودية)، نموذج عرض سعر يفتح واتساب، أسئلة شائعة |

المنتجات السبعة: كروت شخصية، بوكسات بخور، بوكسات حلويات، أكياس فاخرة، دعوات زفاف ومناسبات، أكواب ورقية مطبوعة، ستيكرات وملصقات.
صور المنتجات حالياً مرسومة بالكود (توضيحية)، وستُستبدل بصور الأعمال الفعلية.

**بلغتين:** كل الصفحات بالعربي على الجذر، وبالإنجليزي تحت `/en/` (زر EN / ع في الهيدر يفتح نفس الصفحة باللغة الثانية).
**الوضع الداكن والفاتح:** يتبع إعداد جهاز الزائر أول مرة، وزر القمر/الشمس في الهيدر يبدّل ويحفظ الاختيار.
**أزرار ثابتة:** اتصال (أعلى اليسار بالعربي)، واتساب (أسفل اليسار)، العودة للأعلى (أسفل اليمين، يظهر بعد أول شاشة).

## المحتوى

```
src/
  data/site.ar.json   كل المحتوى بالعربي: الاسم، الأرقام، ساعات العمل، المنتجات، الآراء، الأسئلة (الأساس)
  data/site.en.json   النصوص الإنجليزية فقط، فوق العربي بنفس المفاتيح (الأرقام والصور تبقى من العربي)
  data/ui.ar.json     كلمات الواجهة بالعربي: الأزرار، العناوين، عناوين الصفحات
  data/ui.en.json     نفسها بالإنجليزي
  templates/          قوالب الصفحات (Jinja2): base + partials + صفحة لكل نوع، نفسها للغتين
  static/             css و js والخطوط والصور و Three.js (تُنسخ إلى docs/assets)
  static/js/live.js   الرسم الحي ثلاثي الأبعاد للأجهزة القوية
  scenes/             مشاهد Three.js: common.js (المسرح)، kit.js (الكروت والعلب)، story.js (الرئيسية)، ومشهد لكل منتج
  render.html         يرسم مشهداً كادراً كادراً ويحفظه
  build.py            يبني الموقع كاملاً في docs/
docs/                 الموقع المنشور (GitHub Pages يقرأ من هنا)
  frames/<مشهد>/      كادرات الفيلم: desktop (1600×900) و mobile (810×1620) وأربعة ألواح صغيرة لكل واحد
  gallery/<مشهد>/     ٦ صور معرض 1600×1200 مع نسخ مصغّرة 720×540
logo/                 نسخ اللوغو بالألوان التي جرّبناها
tools/
  render_scene.py     يرسم المشاهد بمتصفح Edge مخفي ويبني الألواح الصغيرة والصور المصغّرة
  frame_server.py     سيرفر محلي يستقبل الكادرات ويحفظها، ويعرض المستودع على 8766
  bench.js            اختبار سرعة: يمرّر بالصفحة ويقيس الإطارات بالثانية والتوقفات
  run_bench.py        يشغّل الاختبار بنافذة Edge أو Chrome حقيقية ويكتب النتيجة في tools/bench.log
run-site.bat          يشغّل الموقع على ويندوز ويفتحه بالمتصفح
```

## تعديل النصوص أو الصفحات

عدّل ملفات `src/data/` أو القوالب في `src/templates/`، ثم:

```bash
python -I src/build.py
```

## إعادة رسم مشهد

كل مشهد يُعرض بطريقتين:
- **رسم حي** على الأجهزة القوية (آيفون، سامسونج الحديثة، اللابتوبات الحديثة): نفس المشهد يُرسم بالمتصفح بدقة الشاشة نفسها و٦٠–١٢٠ إطار بالثانية، فلا تغبيش ولا تقطيع.
  الجهاز يقيس نفسه أولاً (لازم يرسم الإطار بأقل من ١٠ ملّي ثانية)، وإذا تأخر لاحقاً يخفّض الدقة ثم يرجع للكادرات.
- **كادرات مرسومة مسبقاً** على باقي الأجهزة (كروت الشاشة القديمة، الموبايلات الضعيفة، توفير البيانات): الصفحة تعرض الصورة المناسبة لموضع السكرول.

للتجربة: `#debug` بآخر الرابط يبيّن أي طريقة شغّالة ولماذا، و`?live` يتخطى فحص نوع الجهاز (ويبقى قياس السرعة)،
و`?live=force` يتخطى القياس كمان، و`?frames` يفرض الكادرات.

بعد أي تعديل على `src/scenes/` لازم تُعاد الكادرات:

```bash
python -I tools/frame_server.py
```

ثم في طرفية ثانية (أسماء المشاهد: story cards incense sweets bags invitations cups stickers):

```bash
python -I tools/render_scene.py cards incense
```

`--what=film` للفيلم فقط، `--what=stills` لصور المعرض فقط.

## التشغيل محلياً

على ويندوز: دبل كليك على `run-site.bat`.

أو من أي طرفية (يحتاج Python):

```bash
python -m http.server 8765 --directory docs
```

ثم افتح `http://localhost:8765/`. أضف `#debug` لآخر الرابط لترى عدد الإطارات بالثانية.

## الأداء

لا يوجد 3D في متصفح الزائر. كل فيلم يصل أولاً بأربعة ألواح صغيرة (أولها وحده يغطي الفيلم كله بكل رابع كادر)،
ثم تأتي الكادرات الحادة من مكان القارئ. الكادرات تُفكّ خارج الخيط الرئيسي (createImageBitmap)، فلا يُرسم كادر قبل أن يكون جاهزاً.

قياس حقيقي على لابتوب ٢٠١١ (Intel HD Graphics 3000، شاشة 1366×768)، تمرير ١٤ ثانية:

| الطريقة | إطار/ثانية | توقفات طويلة | أطول توقف |
|---|---|---|---|
| بدون كادرات أصلاً | 39.7 | 0 | 0 |
| **كادرات JPG (المعتمد)** | **39.7** | **0** | **0** |
| فيديو H.264 | 39.7 | 1 | 62 ms |
| كادرات WebP | 34.7 | 10 | 401 ms |

على نت بطيء: الألواح الصغيرة تقيس سرعة الخط، فإذا كان بطيئاً تُطلب ٣ كادرات حادة فقط بنفس الوقت (بدل ١٢)، والكادر الظاهر أولاً.
وإذا وقف الزائر على كادر غير حاد تُلغى التحميلات البعيدة عنه حتى يصل كادره. الخطوط محفوظة داخل الموقع نفسه
(من Google كانت تصل بعد ١٠–٢٠ ثانية على VPN، وتبديلها وقت السكرول كان يسبب توقفات لحد نصف ثانية).

قياس على الرابط الحقيقي عبر VPN بطيء (١٥٠–٢٧٠ كيلوبايت/ثانية)، Chrome على نفس اللابتوب:

| القياس | النتيجة |
|---|---|
| إطار/ثانية أثناء السكرول | 39.8 (سقف الجهاز) |
| أطول إطار | 28–51 ms |
| تأخر الصورة عن السكرول | 0 كادر |
| أول صورة حادة بعد فتح الصفحة | 0.6–2 ثانية |
| الصورة تصبح حادة بعد التوقف عند قسم جديد | 1–2.3 ثانية |

لتجربة نت بطيء محلياً: `FRAME_SERVER_KBPS=150 FRAME_SERVER_RTT_MS=250 python -I tools/frame_server.py` ثم `python -I tools/run_bench.py 2 http://localhost:8766/docs/ chrome`.
السيرفر المحلي بطيء مع الطلبات المتوازية، فالقياس الحقيقي للحدّة يكون على الرابط المباشر.

## SEO

كل صفحة فيها عنوان ووصف ورابط canonical وبيانات Open Graph، وبيانات منظّمة (LocalBusiness، BreadcrumbList، Service، FAQPage).
البناء يولّد `sitemap.xml` و`robots.txt` و`llms.txt` (ملخّص للمطبعة لمحركات الذكاء الاصطناعي).
أكواد التتبع (GTM، GA4، Meta، Snapchat، TikTok) تُضاف لاحقاً.
