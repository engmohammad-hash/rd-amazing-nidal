# RD Amazing — موقع المطبعة

موقع مطبعة **RD Amazing** للمطبوعات الفاخرة في المملكة العربية السعودية.
المرحلة الحالية: موقع ثابت (HTML/CSS/JS)، وبعدها يتحوّل إلى PHP + MySQL مع لوحة تحكم.

**الموقع مباشر:** https://engmohammad-hash.github.io/rd-amazing-nidal/

## المحتوى

```
index.html         صفحة GitHub Pages الرئيسية (مولَّدة، لا تعدّلها يدوياً)
demo/
  index.html       المصدر: الصفحة الرئيسية (بدون <!doctype>)
  local.html       نفس الصفحة كمستند كامل للتشغيل المحلي (مولَّدة)
  assets/          اللوغو مقصوص بخلفية شفافة (ملوّن، وبيج للخلفيات الغامقة)
  frames/desktop/            ٢٠٠ كادر JPG حاد 1280×720 للكمبيوتر (5.1 ميغا)
  frames/desktop-small-0..3  ٤ ألواح، كل واحد فيه ٥٠ كادر صغير (١٠٠ كيلوبايت لكل لوح)
  frames/mobile/             ٢٠٠ كادر JPG حاد 720×1440 للموبايل (5.4 ميغا)
  frames/mobile-small-0..3   نفس الشي للموبايل
logo/              نسخ اللوغو بالألوان التي جرّبناها، وصور المقارنة
tools/
  scene.js         المشهد ثلاثي الأبعاد (Three.js): يُستخدم للرسم المسبق فقط
  render.html      يرسم المشهد كادراً كادراً ويحفظه في demo/frames
  frame_server.py  سيرفر محلي يستقبل الكادرات ويحفظها، ونتائج اختبار السرعة
  bench.js         اختبار سرعة: يمرّر بالصفحة ويقيس الإطارات بالثانية والتوقفات
  run_bench.py     يشغّل الاختبار بنافذة Edge حقيقية ويكتب النتيجة في tools/bench.log
  build_site.py    يولّد index.html و demo/local.html من demo/index.html
run-demo.bat       يشغّل الديمو على ويندوز ويفتحه بالمتصفح
```

بعد أي تعديل على `demo/index.html` شغّل `python tools/build_site.py` ثم ارفع التغييرات.

### إعادة رسم الكادرات

المشهد لا يعمل في متصفح الزائر؛ هو مرسوم مسبقاً كصور، والصفحة تعرض الصورة المناسبة لموضع السكرول.
بعد أي تعديل على `tools/scene.js`:

```bash
python tools/frame_server.py
```

ثم افتح `http://localhost:8766/tools/render.html` في متصفح ظاهر وغير مصغّر (المتصفح يبطّئ التبويبات المخفية)،
وانتظر حتى يظهر `ALL DONE`.

## التشغيل محلياً

على ويندوز: دبل كليك على `run-demo.bat`.

أو من أي طرفية (يحتاج Python):

```bash
python -m http.server 8765 --directory demo
```

ثم افتح `http://localhost:8765/local.html`.
لا تفتح الملف مباشرة بدبل كليك: المتصفح يمنع رسم الصور داخل الـ3D من `file://`.

أضف `#debug` لآخر الرابط لترى عدد الإطارات بالثانية وكرت الشاشة المستخدم.

## الصفحة الرئيسية

قصة تتحرك مع السكرول بأربع مراحل، مرسومة بالكود بـ Three.js ثم محفوظة كصور:
**صمّم** (التصميم يُرسم على الورقة) ← **اطبع** (الورقة تمر بين رولين الطباعة)
← **فخامة** (ختم حراري بيج على كرت عنابي) ← **استلم** (الكروت في علبة فاخرة).

الأداء: لا يوجد 3D في متصفح الزائر. الصفحة تحمّل الكادرات من الأقرب للأبعد
(أول كادر، ثم كل ٣٢، ثم كل ١٦…) فيظهر المشهد فوراً. الكادرات تُفكّ مسبقاً خارج الخيط الرئيسي
(createImageBitmap) حول موضع القارئ فقط، فلا يُرسم كادر قبل أن يكون جاهزاً.

قياس حقيقي على لابتوب ٢٠١١ (Intel HD Graphics 3000، شاشة 1366×768)، تمرير ١٤ ثانية:

| الطريقة | إطار/ثانية | توقفات طويلة | أطول توقف |
|---|---|---|---|
| بدون كادرات أصلاً | 39.7 | 0 | 0 |
| **كادرات JPG (المعتمد)** | **39.7** | **0** | **0** |
| فيديو H.264 | 39.7 | 1 | 62 ms |
| كادرات WebP | 34.7 | 10 | 401 ms |

يعني الكادرات لا تكلّف شيئاً فوق الصفحة نفسها.

على نت بطيء ومتأخر (١٣٠ كيلوبايت/ثانية، ٣٠٠ ملّي ثانية لكل طلب): حركة القصة كلها تصل بأربع طلبات صغيرة (أولها وحده يغطي القصة كلها بكل رابع كادر)
قبل أي كادر حاد، فالصورة لا تتأخر عن السكرول أبداً (٠٫١ كادر) وتصبح حادة تدريجياً من مكان القارئ.
لتجربة ذلك: `FRAME_SERVER_KBPS=130 FRAME_SERVER_RTT_MS=300 python tools/frame_server.py` ثم `python tools/run_bench.py 2 http://localhost:8766/demo/local.html chrome`. لإعادة الاختبار: شغّل `tools/frame_server.py` ثم `python tools/run_bench.py`.
